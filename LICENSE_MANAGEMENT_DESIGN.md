# G-TRADE ERP — Licence Management Design

**Date:** 2026-11-11 · **Status:** Design for review. Nothing implemented.
Parent document: `COMMERCIAL_WINDOWS_ARCHITECTURE.md`.

---

## 1. Current state

| Item | State |
|---|---|
| `config/license.json` | Demo JSON (`DEMO-LICENSE-OPTICAL-ERP-2026`, `ENTERPRISE_SINGLE_PC`, valid 2099). **No code reads it.** |
| Packages / modules | ✅ `apps/common/module_access.py` (`MODULES`, `PACKAGES`), `Tenant.package`, `Tenant.modules`, write gate `install_api_gate` |
| Seat limit | ✅ `Tenant.max_users`, enforced at user creation and `/api/auth/register/` |
| Branch / company limits | ❌ |
| Registration, activation, expiry, revocation | ❌ |
| Licensing server | ❌ |

The existing module and seat machinery is the **enforcement point**. Licensing only needs to feed it
trusted values and add the company/branch counters.

## 2. Goals and non-goals

Goals:
1. Customer registration and activation (online, offline fallback).
2. Enforce limits for companies, branches, users and modules, plus edition and expiry.
3. Licence verified **on the server**, never in the browser or Electron client.
4. Work offline for long periods (shops lose internet).
5. Transfer to new hardware without vendor intervention most of the time.

Non-goals:
- Unbreakable DRM. Python runs on customer hardware; a determined attacker can patch it. The design makes
  bypass **deliberate, detectable and contractually clear**, not impossible.
- Licensing workstations. They are clients of the server; users are counted there.

## 3. Licence model

```jsonc
// license.lic  = base64url(payload) + "." + base64url(Ed25519 signature)
{
  "lic_id": "L-2026-000123",
  "org_id": "c7a1…",                    // binds to the Organization created at install
  "customer": {"name": "…", "email_hash": "sha256:…"},   // minimal personal data
  "edition": "STANDARD|PROFESSIONAL|ENTERPRISE",
  "deployment": "STANDALONE|LAN",
  "limits": {"companies": 2, "branches_per_company": 3, "branches_total": 5,
             "users": 10, "workstations": null},
  "modules": ["sales","inventory","purchase","accounts", "..."],   // keys from module_access.MODULES
  "issued_at": "2026-11-11T00:00:00Z",
  "valid_until": "2027-11-10T23:59:59Z",        // null = perpetual
  "updates_until": "2027-11-10T23:59:59Z",      // update entitlement (perpetual licences)
  "grace_days": 30,
  "machine": {"fp_v": 1, "fp": "sha256:…", "tolerance": 2},
  "activation_id": "A-…",
  "key_id": "gtl-2026-1"                         // which vendor public key signed it
}
```

- Signing: **Ed25519**. The private key lives only in the licensing service's KMS/HSM. Public keys (current +
  next, for rotation) are embedded in the backend build.
- The trial licence is a signed file generated by the licensing service on registration, or a built-in 30-day
  trial keyed to the install id (limits: 1 company, 1 branch, 2 users).

## 4. Machine binding (server/standalone only)

Fingerprint v1 = SHA-256 over normalised components, each hashed separately:
`MachineGuid` (registry), system drive volume serial, motherboard/BIOS UUID (`Win32_ComputerSystemProduct.UUID`),
CPU id, primary non-virtual MAC.

- Match rule: valid if ≥ (N − tolerance) components match, so a NIC or disk change does not lock the shop out.
- A virtual machine is allowed (UUID from the hypervisor). A clone is detected online by a duplicate `activation_id`
  check-in from two fingerprints.
- **The fingerprint never leaves as raw values**; only salted hashes are sent.

## 5. Enforcement points (backend, `GTRADE_EDITION=local`)

| Limit | Enforced at | Mechanism |
|---|---|---|
| Valid signature, `org_id` matches, fingerprint matches | Service start + every 6 h (Agent) + on every licence-sensitive write | `apps/licensing/verifier.py` (new). The result is cached in memory and in a `LicenseState` row. |
| Expiry / grace | Middleware on `/api/` writes | Expired beyond grace → **read-only mode**: writes return 402 with a clear message; reads, reports, exports and backups keep working. **Data is never locked away.** |
| Companies | Company create (`onboard_tenant` call site), company reactivate | Count active tenants in the org |
| Branches | `BranchViewSet.create`, `activate` | Per company and total |
| Users | Existing seat check: set `Tenant.max_users` / org-level count from the licence | Active users across the org (named users, decision D5) |
| Modules | Existing `module_access` gate | Licence modules ∩ tenant modules; the licence wins |
| Edition / deployment | `STANDALONE` licence refuses non-loopback binding (`gtrade-ctl` + health) | Config check |
| Updates | Update agent compares `updates_until` with the release date | Newer releases need an entitlement; the current version keeps working forever (perpetual) |

The frontend only **displays** licence state (`/api/licensing/status/`): days left, limits used/available.
It never decides.

## 6. Activation flows

### 6.1 Online (default)
```
Installer/Server Manager → gtrade-ctl license activate --key XXXX-…  (via the secrets temp file)
  → POST https://license.<vendor>/v1/activate {key, install_id, fp_hashes, org_id, app_version}
  ← signed license.lic (bound to fp + org_id), activation_id
  → verify signature with the embedded public key → store C:\ProgramData\G-TRADE\config\license.lic
```
TLS with certificate pinning to the vendor's CA. Rate-limited, and activations per key are capped (default 2 active).

### 6.2 Offline
1. `gtrade-ctl license request` → `activation-request.gtr` (key, install id, fp hashes, signed by the install key).
2. The customer uploads it on the vendor portal from any internet device (or a reseller does).
3. The portal returns `license.lic` → imported through the installer or Server Manager.

### 6.3 Renewal / check-in
- The Agent checks in every 24 h when online: fetches a renewed licence, the revocation list, and update metadata.
- Offline is fine until `valid_until`. Perpetual licences never need a check-in to run.
- **Subscription** licences: issued for `period + grace`; renewal requires a check-in within the grace window, or an offline renewal file.

### 6.4 Revocation
- A signed CRL (list of `lic_id`/`activation_id`) is fetched at check-in. Revocation → read-only mode after a 7-day notice.
- Used for refunds, fraud and transferred licences.

## 7. Transfer and recovery

| Case | Flow |
|---|---|
| New server hardware | Server Manager → "Deactivate" (online frees the slot; offline produces a signed deactivation receipt) → activate on the new PC. If the old PC is dead: portal self-service transfer, limited to 2 per year, then vendor support. |
| Restore backup on a new PC | The backup carries `org_id`; the licence re-activates against the new fingerprint |
| Fingerprint drift beyond tolerance | 14-day grace with a banner; one-click online re-bind |

## 8. Anti-tamper (proportionate)

| Threat | Mitigation |
|---|---|
| Editing `license.lic` | Signature fails → trial/read-only mode |
| Copying a licence to another PC | Fingerprint check; duplicate check-in detection |
| Rolling the clock back to extend expiry | `LicenseState.last_seen_utc` (DB) + file timestamp + PostgreSQL `now()` + newest journal/invoice timestamp: if wall clock < max(last seen) − 48 h → "clock tamper" banner and grace counter does not reset |
| Patching the verifier in `.pyc` | Ship `.pyc` only; integrity manifest signed and checked by the Agent at start; licence checks in several modules (company/branch/user create paths call the verifier directly). Residual risk accepted (C4). |
| Direct DB edits (raising `max_users`) | Limits are always taken from the licence at check time, never trusted from DB columns |
| Replay of an old licence after revocation | `issued_at` must be ≥ the newest seen `issued_at`; CRL is cached |

## 9. Licensing service (vendor side, new)

- Separate small service (FastAPI/Django) with its own database. **Not** part of the ERP cloud app or its DB.
- Entities: Customer, Order, LicenceKey, Activation, CheckIn, Revocation, Reseller.
- Endpoints: `register`, `activate`, `deactivate`, `checkin`, `offline/request`, `offline/response`, `crl`, `updates/channel`.
- Admin/reseller portal: issue keys, see activations, transfer, revoke, trial extension.
- Signing in KMS/HSM; audit log of every issued licence; daily backups.
- Privacy: store the minimum (company name, contact email, hashed fingerprints, IP at activation for fraud only, with a retention limit).

## 10. Client registration (in-product)

- Trial start in the installer: name, company, email, phone, country. Sent only with consent at activation (or entered on the portal for offline).
- "About & Licence" screen in Settings: licence id, edition, limits used/total, expiry, update entitlement,
  buttons Activate / Renew / Import file / Deactivate (org admin + re-auth).

## 11. Cloud edition

Unchanged. Cloud tenants keep packages and seats set by the platform Super Admin console. The verifier is
active only under `GTRADE_EDITION=local`. A shared `entitlements` interface (`get_entitlements(org)`) lets both
editions feed the same `module_access` and seat checks.
